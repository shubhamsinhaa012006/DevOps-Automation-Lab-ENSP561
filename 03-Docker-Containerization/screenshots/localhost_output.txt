        <section class="intro card">
            <h2>Understanding Docker</h2>
            <p><strong>Docker</strong> is an open-source platform designed to automate the deployment, scaling, and management of applications using containerization. It packages an application and its dependencies into a standard unit of software development called a container.</p>
        </section>

        <section class="grid-container">
            <article class="info-card">
                <div class="icon">🐳</div>
                <h3>Containerization</h3>
                <p>The process of isolating an application and its environment into a portable unit. It ensures the application runs consistently across any environment, from development to production.</p>
            </article>
            
            <article class="info-card">
                <div class="icon">📦</div>
                <h3>Docker Images</h3>
                <p>A read-only, immutable template containing the application code, runtime, libraries, environment variables, and config files needed to run a container.</p>
            </article>
            
            <article class="info-card">
                <div class="icon">⚙️</div>
                <h3>Docker Containers</h3>
                <p>A lightweight, standalone, and runnable instance of a Docker image. Containers share the host system's OS kernel but operate in isolated user spaces.</p>
            </article>

            <article class="info-card">
                <div class="icon">📜</div>
                <h3>Dockerfile</h3>
                <p>A text-based script of instructions that Docker uses to automatically build an image. It defines the base image, environment variables, required files, and execution commands.</p>
            </article>
        </section>

        <section class="benefits card">
            <h2>Benefits of Docker</h2>
            <ul class="benefits-list">
                <li><strong>Portability:</strong> Build once, run anywhere. Eliminates the "it works on my machine" problem.</li>
                <li><strong>Efficiency:</strong> Less overhead than virtual machines since containers share the host kernel.</li>
                <li><strong>Isolation:</strong> Each container has its own isolated resources, preventing conflicts between applications.</li>
                <li><strong>Scalability:</strong> Easily spin up multiple container instances to handle increased load.</li>
                <li><strong>CI/CD Integration:</strong> Seamlessly integrates with continuous integration and deployment pipelines.</li>
            </ul>
        </section>
